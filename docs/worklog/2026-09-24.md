## 1. 6.8 — PDPA erasure: pseudonymize แทนการลบ (review B10 · PCI 10.5.1)

### ปัญหา
`DELETE /api/v1/erasure/user/:userId` **ลบ** แถว `audit_access` ของ user · PCI DSS 10.5.1 ให้เก็บ audit trail ≥ 12 เดือน

### ที่แก้
- `src/erasure/erasure.service.ts` — ใน transaction เดียวกับ tombstone:
  - แถวของ user: `user_id` → `anon-<HMAC-SHA256(key, userId)>` · `username` / `ip_address` → NULL
    (`ip_address` เป็น `inet` ใส่ hash ไม่ได้ และ IP ระบุตัวคนได้ → NULL)
  - แถวอื่นที่มี userId ใน `resource` (admin แก้ role ของ user นี้ · URL ของคำขอลบที่เคยทำ) → แทนด้วย HMAC ตัวเดียวกัน
    จับเฉพาะตอนเป็น segment เต็มของ URL (`resourcePattern()` — `(^|[/=])id(?=[/?&#]|$)`) ไม่งั้น id สั้น ๆ แก้ทุกแถว ·
    `left(…, 256)` กันล้นความยาวคอลัมน์ (pseudonym 69 ตัวยาวกว่า UUID)
  - 404 ดูจากแถวของ user เองเท่านั้น (ดูหัวข้อ "เจอระหว่างทดสอบ")
  - ไม่มี key → **503** ไม่ถอยไปลบจริง (ขัด PCI) หรือ hash เปล่า (UUID ของ Keycloak ไล่ hash ย้อนได้)
  - userId ขึ้นต้น `anon-` → 400
- key: `infra/vault/init.sh` สุ่มด้วย `sys/tools/random/32` ของ Vault **ครั้งแรกครั้งเดียว** → `secret/logchain/erasure pseudonym_key`
  (ไม่ได้มาจาก `.env` — seed ใหม่ทุกรอบแล้ว pseudonym ของคำขอเก่ากับใหม่จะไม่ตรงกัน) · `nestjs-policy.hcl` ให้อ่าน ·
  `VaultService.readPseudonymKey()` ไม่มี = warn + erasure ใช้ไม่ได้ ไม่ใช่ boot ไม่ขึ้น
- URL ของคำขอลบเอง: `ErasureController` ตั้ง `req.auditResource` (id → pseudonym) · `AuditInterceptor` ใช้ `req.auditResource ?? req.url`
- migration `ErasurePseudonymize1790467200000` — `erasure_log` เพิ่ม `method` (DEFAULT `'DELETE'` = แถวเก่า) + `pseudonym`
  · หน้า Reports / compliance API คืนสองฟิลด์นี้เพิ่ม · `records_deleted` = จำนวนแถวที่ถูก pseudonymize สำหรับ method ใหม่
- ผู้ถือ key ตามรอยได้: `HMAC(key, userId)` แล้ว `select … from audit_access where user_id = 'anon-…'` — ตั้งใจ (สืบสวนตาม PCI 10)

### เจอเพิ่ม: retention ลบ audit ที่ 90 วัน
`RetentionService` ใช้ `RETENTION_DAYS ?? 90` ทั้ง `alerts` และ `audit_access` · compose **ไม่ส่ง** `RETENTION_DAYS` เข้า backend

(`retentionDays()` + `retention.service.spec.ts`) · `.env.example` 90 → 365

### เจอระหว่างทดสอบ

  ถ้านับ reference เป็น "เจอ" จะออก tombstone ให้ id ที่ไม่เคยเป็น user → เปลี่ยนเป็นดูแถวของ user เอง (ไม่เจอ = rollback ทั้งหมด)
