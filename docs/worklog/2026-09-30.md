## 6. เตรียม deploy ขึ้น cloud (อาจารย์แนะนำ Vercel / Railway / Render ฟรี)

**ประเมิน:** stack ใช้ RAM ~5 GB (`docker stats`: Kafka ×3 ~2.3 GB · Keycloak ~850 MB · Vault ~440 MB · detection ~390 MB)
· Render free 512 MB/service + หลับเมื่อว่าง (cron seal หยุด) · Railway ไม่มี free ถาวร · Vercel = frontend อย่างเดียว
→ **เจ้าของเลือก:** Oracle Always Free VM (ARM 4 OCPU / 24 GB) รัน compose เดิม + dashboard บน Vercel · DuckDNS · เริ่มข้อมูลใหม่

**ตรวจแล้ว:** image ทุกตัวใน compose มี arm64 (`docker manifest inspect` 13 ตัว) · base `node:*-alpine` / `python:3.12-slim` มี arm64
· torch CPU มี wheel aarch64 (ยังไม่ได้ build จริง) · dashboard self-contained (Root Directory `cylis-dashboard` บน Vercel ได้)
· keycloak-js `login-required` + `checkLoginIframe:false` → ข้าม site (vercel.app ↔ duckdns.org) ไม่ต้องพึ่ง third-party cookie
· contract `LogIntegrity` owner-only → cloud ต้อง deploy contract ใหม่ด้วย wallet ใหม่

**ทำ:**
- `docker-compose.cloud.yml` — override เฉพาะ `https-proxy`: `ports: !override` 80→8080 / 443→8443 (container ยัง non-root) ·
  Caddyfile.cloud · `/data` bind `infra/caddy/.data` (cert อยู่ข้าม restart) · ใช้ผ่าน `COMPOSE_FILE` ใน `.env` ของ VM
- `infra/caddy/Caddyfile.cloud` — `{$AUTH_HOST}` → keycloak · `{$API_HOST}` → backend · Let's Encrypt · redirect http→https เอง
  (auto redirect จะพาไป :8443) · `caddy validate` + `caddy fmt` ผ่าน · `docker compose config` merge ถูก (Kafka ยัง 127.0.0.1)
- `docs/runbooks/deploy-cloud.md` — ขั้น A–I (บัญชี · VM · Vercel · .env · bootstrap · blockchain · ตรวจ · ดูแล · ความเสี่ยงที่ต่างจาก local)
