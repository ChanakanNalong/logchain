## 2. `https://localhost:3453` ของ clone เปิดไม่ได้ — CA ชื่อซ้ำ → `2afc52e`

- เซิร์ฟเวอร์ปกติ (`curl --cacert` = 200) · Chrome ขึ้น `NET::ERR_CERT_AUTHORITY_INVALID`
- ทั้งสองชุดสร้าง CA ชื่อ `LogChain-Web-CA` แต่คนละ key · NSS เก็บ nickname นี้ได้ใบเดียว — ใน store เป็นใบของชุดจริง (`A7:30:DD…`)
  ไม่ใช่ของ clone (`27:35:D8…`) · Chrome บน Linux ยังรันค้างเบื้องหลังหลังปิดหน้าต่างด้วย
- ทดสอบด้วย headless Chrome + NSS DB ใหม่ใส่ CA ของ clone ใบเดียว → เปิดได้ ยืนยันว่าเป็นที่ trust store
- เจ้าของลบ nickname เดิมทั้งหมด + `trust-web-ca.sh` ของ clone + ปิด Chrome จริง → เปิดได้

**แก้ถาวร (`2afc52e`):** `infra/tls/gen-certs.sh` ตั้งชื่อ CA `LogChain-Web-CA (<compose project>)`
(project: env → `.env` → `name:` ใน compose) · `bootstrap.sh` ส่ง `$PROJECT` ให้ · `trust-web-ca.sh` อ่านชื่อจาก CN ของ `ca.crt`
· CA ที่มีอยู่แล้วคงชื่อเดิม (สร้างใหม่เฉพาะตอนไม่มี `ca.key`)
- ทดสอบใน scratchpad: 3 ทางได้ชื่อถูก · trust 3 ใบ (2 ชื่อใหม่ + ชื่อเก่า) ใน NSS เดียวกันได้ · สร้าง CA ใหม่แล้ว trust ซ้ำ = แทนที่ไม่ซ้อน · `--remove` ลบเฉพาะของตัวเอง
- บั๊กที่เจอระหว่างเขียน: ไม่มี `.env` + `pipefail` → สคริปต์ตายเงียบ แก้แล้ว
- macOS / Windows ค้นชื่อแบบ substring — วงเล็บปิดกันชื่อใหม่ชนกัน แต่ CA **ชื่อเก่า** ยังไปโดนของ clone อื่น (Linux ไม่เป็น) · ยังไม่ได้ทดสอบบน macOS / Windows

## 8. PII masking ของ backend ทำให้ HDFS 66% เป็น unknown (ยังไม่ commit)

ก่อนเข้า Kafka — ตอน train ไม่มี · จำลองกับ `HDFS.log` ทั้งไฟล์: **66% ไม่ตรง template** (แล้วถูกข้ามเงียบจากหัวข้อ 7)
