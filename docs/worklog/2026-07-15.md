## 1. Vault — Secrets Management (งานหลักของวันนี้)

ย้าย secret ทั้งหมดออกจาก `.env` ไปเก็บใน HashiCorp Vault (server mode + file storage,
ไม่ใช่ dev mode → ข้อมูลรอด restart แต่ต้อง unseal ทุกครั้งที่ตื่นมา)

**ไฟล์ใหม่**
- `infra/vault/config/vault.hcl` — server config (file storage backend)
- `infra/vault/unseal.sh` — init + unseal + เก็บ root token/unseal keys ลง `.secrets/init.env`
- `infra/vault/init.sh` — seed secrets + สร้าง policy + AppRole
- `infra/vault/policies/nestjs-policy.hcl` — NestJS อ่าน database/keycloak/blockchain
- `infra/vault/policies/detection-policy.hcl` — detection อ่านได้แค่ `secret/logchain/detection`
- `src/vault/vault.service.ts` — AppRole login (มี retry + backoff), โหลด secret แบบ memoized

**ไฟล์ที่แก้**
- `src/vault/vault.module.ts` — ทำเป็น `@Global()` module, export `VaultService`
- `src/app.module.ts` — TypeORM ดึง **DB password จาก Vault** แทน `DATABASE_URL`
  (VaultModule ต้องถูก import ก่อน TypeOrmModule; useFactory `await vault.init()`)
- `src/blockchain/blockchain.service.ts` — **private key มาจาก Vault** ไม่ใช่ `.env`
- `docker-compose.yml` — เพิ่ม `vault`, `vault-unseal`, `vault-init` (hashicorp/vault:1.18)
- `.gitignore` — ignore `infra/vault/.secrets/` และไฟล์สำรอง `.env.*.bak`

**Secret paths ที่ seed**
`secret/logchain/{database, keycloak, blockchain, detection}`

## 6. งานทดสอบ / debug ที่ทำในเซสชันนี้

### ✅ ยืนยันว่าใช้งานได้ (end-to-end)
- ขอ token ผ่าน Keycloak `client_credentials` (client `log-ingestor`) โดยดึง
  `ingestor_secret` จาก Vault → ยิง log ที่มี SQLi pattern เข้า `POST /api/v1/logs`
  → เข้า DB สำเร็จ
- Detection service จับได้: alert `RULE_MATCH` (rule_id **31100**, "SQL injection pattern detected",
  severity CRITICAL) ใน topic `alerts.raw`
- IP enrichment: `ip_intel.geo` resolve `8.8.8.8` → United States สำเร็จ

### ⚠️ ปัญหาที่เจอในสคริปต์ทดสอบ (ยังไม่แก้)
1. **vault CLI 403** — `docker exec logchain-vault vault kv get/put ...` ต้องมี token
   Vault ตัวนี้ production mode ไม่มี `VAULT_TOKEN` ใน container
   **แก้:** ดึง root token แล้วส่งเข้า CLI
   ```bash
   ROOT=$(docker exec logchain-vault-unseal sh -c 'grep "^VAULT_ROOT_TOKEN=" /vault/secrets/init.env | cut -d= -f2')
   docker exec -e VAULT_TOKEN="$ROOT" logchain-vault vault kv get secret/logchain/detection
   ```
   (แนะนำระยะยาว: ทำ token/policy แยกสำหรับอ่าน path นี้ อย่าใช้ root token ประจำ)

2. **kafka-console-consumer timeout สั้นไป** — `--timeout-ms 3000` cold start ไม่ทัน →
   "Processed a total of 0 messages"
   **แก้:** เพิ่มเป็น `10000` + `2>/dev/null` กัน error line ปน stdout

3. **Rotation test ของ detection ยัง validate ไม่ได้** — ฝั่ง logchain เตรียม Vault ครบ
   (path `secret/logchain/detection` + `detection-policy.hcl`) แต่ **image detection service
   ที่รันอยู่ยังอ่าน `ABUSEIPDB_API_KEY` จาก env** (`config.py` → `os.getenv`) ไม่มี vault client
   - consumer จริงรันเป็น `python main.py` ใน container `log_detection` (repo `log-integrity`)
     ไม่ใช่ `python3 -m app.consumer` บน host
   - ไม่มี log `Vault secrets loaded (detection)`
   - **TODO:** ทำ detection consumer ใหม่ใน repo `logchain-detection` (แยกจาก repo นี้)
     ให้โหลด key จาก Vault ด้วย detection AppRole ก่อนถึงจะเทสต์ rotation ได้จริง
     (repo `log-integrity` เดิมเป็น prototype week 1-2 ลบทิ้งแล้ว)
