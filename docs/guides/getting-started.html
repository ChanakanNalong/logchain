sudo apt update

docker compose version             # ต้องขึ้น v2.x

Windows 10 / 11 ยังไม่ได้ทดสอบ

script ของระบบเป็น bash จึงต้องรันใน WSL2 (Ubuntu ที่อยู่ใน Windows)

  1. เปิด PowerShell แบบ Run as administrator แล้วพิมพ์ wsl --install -d Ubuntu → restart เครื่อง → เปิดแอป Ubuntu จากเมนู Start แล้วตั้ง username / password
  2. ติดตั้ง Docker Desktop (docker.com/products/docker-desktop) → Settings → Resources → WSL integration → เปิด Ubuntu
  3. ในหน้าต่าง Ubuntu:
sudo apt update && sudo apt install -y git curl jq openssl python3
docker compose version             # ต้องขึ้น v2.x (มาจาก Docker Desktop)
ทุกคำสั่งในคู่มือนี้ พิมพ์ในหน้าต่าง Ubuntuไม่ใช่ PowerShell หรือ Command Prompt · ส่วนหน้าเว็บเปิดด้วยเบราว์เซอร์ของ Windows ได้ตามปกติ

macOS ยังไม่ได้ทดสอบ

  1. ติดตั้ง Docker Desktop (เลือกรุ่น Apple Silicon หรือ Intel ให้ตรงเครื่อง) → Settings → Resources → Memory อย่างน้อย 6 GB
  2. ใน Terminal:
xcode-select --install             # ได้ git + python3 (ถ้ามีแล้วจะแจ้งว่าติดตั้งอยู่แล้ว)
# Homebrew (ถ้ายังไม่มี) — ดูคำสั่งติดตั้งที่ brew.sh
brew install jq
docker compose version             # ต้องขึ้น v2.x

curl และ openssl มากับ macOS อยู่แล้ว

1Clone โปรเจกต์

cd ~
git clone https://github.com/ChanakanNalong/logchain.git
cd logchain
Windows: clone ในหน้าต่าง Ubuntu และอยู่ในโฟลเดอร์ ~ เท่านั้นห้ามไว้ใต้ /mnt/c/... (ตั้งสิทธิ์ไฟล์ key ไม่ได้ → Kafka ขึ้นไม่ได้ และช้ามาก) · ห้าม clone ด้วย Git for Windows (จะเจอ /bin/bash^M: bad interpreter)

2ยกทั้งระบบ — คำสั่งเดียว

./scripts/bootstrap.sh

script จะทำให้ทั้งหมด: สุ่มรหัสผ่านทุกตัวลงไฟล์ .env · สร้าง certificate · เปิดฐานข้อมูล, Vault, Kafka, Keycloak · build และเปิด backend, dashboard, ระบบตรวจจับ

  • ครั้งแรกบนเครื่องใหม่ต้อง build image — ราว 10–20 นาที (ครั้งต่อไป 2–3 นาที)
  • Windows / macOS: เปิด Docker Desktop ค้างไว้ก่อนรัน
  • จบแล้วต้องเห็นกรอบ “LogChain พร้อมใช้งาน” พร้อมรายการ URL

ตรวจว่าทุกอย่างขึ้นครบ:

docker compose ps      # ทุกตัวต้องเป็น Up / healthy — ไม่มี Restarting

5ยิงข้อมูล demo ให้หน้าเว็บมีอะไรให้ดู

ระบบที่เพิ่งติดตั้งยังไม่มี log เลย — ใช้ script ยิงข้อมูลตัวอย่าง (รันในโฟลเดอร์ logchain):

# 1) log 1 รายการ — เลขบัตรในข้อความจะถูก mask เป็น [PAN] ก่อนเก็บ
./scripts/ingest-log.sh

# 2) จำลองการเดารหัสผ่าน (brute force) 6 ครั้ง → ระบบตรวจจับแล้วออก alert
set -a; . ./.env; set +a
T=$(curl -sf -X POST http://localhost:8080/realms/logchain/protocol/openid-connect/token \
  -d grant_type=client_credentials -d client_id=log-ingestor \
  -d "client_secret=$LOGCHAIN_INGESTOR_SECRET" | jq -r .access_token)
./scripts/demo-brute-force.sh "$T"

หน้าสิ่งที่ควรเห็น
Logslog ที่ยิงเข้าไป — ข้อมูลส่วนตัวถูก mask แล้ว
Alertsalert ระดับ CRITICAL “Multiple authentication failures (brute force)”
Integritybatch สถานะ SEALED — log ถูกรวมเป็น Merkle root ทุก 1 นาที · จะขึ้น CONFIRMED (บันทึกบน blockchain) ต้องใส่ BLOCKCHAIN_PRIVATE_KEY ใน .env เอง (ไม่บังคับ)

6ใช้งาน dashboard

เมนูอยู่แถบซ้าย · admin-user มีครบทุก role จึงเห็นทุกเมนู (บัญชีอื่นเห็นตาม role ของตัวเอง)

เมนูใช้ทำอะไรrole ที่ต้องมี
Dashboardภาพรวม: จำนวน log · Chain Integrity (%) · กราฟปริมาณ log (เลือกช่วง 1H – All) · IP ต้นทางที่เจอบ่อย · log ล่าสุดanalyst · operator · admin
Logsค้นหาด้วย ID / source / IP / event · กรองตามประเภทการโจมตีและ severity · เลื่อนหน้าanalyst · operator · admin
ML Detectionผลการ train โมเดล DeepLog (confusion matrix) + การตรวจจับที่เกิดขึ้นจริงในระบบanalyst · operator · admin
Datasetข้อมูลอ้างอิงของ dataset HDFS ที่ใช้ train (ข้อมูลคงที่ ไม่ได้ดึงจากระบบ)–
Verifyสถานะ chain (Integrity · Sealed · Tampered · Anchored) + ตรวจ Merkle proof ของ log ทีละรายการanalyst · operator · admin
Alertsรายการ alert · กรองตาม status / severity / ประเภท · กดแถวเพื่อดูรายละเอียด · ปุ่ม Resolveดู: analyst ขึ้นไป · Resolve: operator · admin
Reportsรายงาน compliance ตามช่วงวันที่ (integrity รายวัน · audit · คำขอลบข้อมูล PDPA) · ปุ่ม Export CSVauditor · admin
Settingsจัดการผู้ใช้: เพิ่ม / ถอด role · ปิดบัญชี (ถอด admin ของตัวเองหรือคนสุดท้ายไม่ได้ — ระบบกันไว้)admin

ลองทำตาม 3 สถานการณ์

ก. เจอการโจมตี → จัดการ alert

  1. รันขั้นที่ 5 (brute force) แล้วรอ ~1 นาที
  2. เมนู Alerts → ตั้งตัวกรอง status เป็น OPEN → เห็น alert CRITICAL “Multiple authentication failures (brute force)”
  3. กดที่แถวเพื่อดูรายละเอียด (host · จำนวนครั้งที่เกิดซ้ำ) → กด Resolve → status เปลี่ยนเป็น RESOLVED

ข. พิสูจน์ว่า log ไม่ถูกแก้

  1. เมนู Verify → การ์ด Chain status ต้องขึ้น Chain integrity 100% และ Tampered 0
  2. ในรายการ log ล่าสุด กดปุ่ม Verify ของ log ใดก็ได้ → ต้องขึ้น “Verified — proof valid” พร้อม hash ที่คำนวณใหม่ · Merkle path · root ของ batch
  3. ถ้าขึ้น “Log not found, or not yet sealed into a batch” = log เพิ่งเข้า ยังไม่ถูกปิด batch — รอ 1 นาทีแล้วลองใหม่

batch สถานะ SEALED = ตรวจความถูกต้องในเครื่องทุกนาทีแล้ว · CONFIRMED = บันทึก root บน blockchain ด้วย (ต้องตั้ง BLOCKCHAIN_PRIVATE_KEY)

ค. ออกรายงาน

  1. เมนู Reports → เลือกช่วงวันที่ From / To
  2. ดูตาราง integrity รายวัน (Tampered · Unverified · Pending) และสถิติ audit
  3. กด Export CSV → ได้ไฟล์ compliance_<from>_<to>.csv
